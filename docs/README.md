# SpaceAce

Вертикальный космический шутер в духе bullet hell для Android, отлаживается на desktop.
Корабль игрока летает в нижней части поля, сбивает метеориты и противников, собирает усилители и деньги,
проходит уровни и боссов. Между забегами сохраняются деньги, купленные корабли, подвесы и открытые записи бестиария (роглайк).

Подробности по отдельным темам:
- [`docs/ARCHITECTURE.md`](ARCHITECTURE.md) — подробный обзор подсистем;
- [`docs/CONTENT_GUIDE.md`](CONTENT_GUIDE.md) — каталог контента и пошаговое добавление противников, боссов, оружия, усилителей, предметов;

## 3. Архитектура

### 3.1. Слои

```
              ввод (input/, ui/UiController)
                         │  ControlState, UiAction
                         ▼
 content/ ──▶  логика (logic/, npc/, weapon/, hazard/)  ◀──▶  физика (physics/, Box2D)
 Config      чистые функции + «системы», применяющие их результат          тела ↔ EntityId
                         │  методы GameState
                         ▼
              состояние (state/: GameState, EntityRegistry, RunState, MetaState)
                         │  только чтение                         │
                         ▼                                        ▼
              рендер (render/)                           сохранения (save/)
```

- **Логика не знает о рендере**, рендер только читает состояние, интерфейс меняет игру только через методы `GameState`.
- **Состояние — неизменяемые data-классы.** Сущности (`Player`, `Meteor`, `Npc`, `Projectile`, `PowerUp`) — снимки:
  каждый шаг сущность заменяется новой копией в `EntityRegistry`. Мутации — только через контролируемые методы,
  которые возвращают `false`, если действие сейчас недопустимо.
- **Box2D ↔ сущности через id.** В `body.userData` лежит `EntityId`; актуальный снимок берётся из реестра.
- **Все числа — в `Config`** (вложенные `object`), числа противников — в их файле в `content/`.
- **Чистые функции без LibGDX** — всё, что можно протестировать: урон, оружие, ИИ, спаун, инвентарь, деньги, геометрия лучей.
  Нечистые «системы» (`PhysicsSystem`, `NpcSystem`, `ProjectileSystem`, `HazardSystem`) только применяют их результат.
- **Исчерпывающие `when`** по sealed-типам и enum: новый снаряд, усилитель или оружие без цвета, подписи или цены
  не скомпилируется.
- **Единицы.** Логика и Box2D — в метрах: 1 м = 100 виртуальных px, поле 7.2 × 12.8 м, виртуальный экран 720 × 1280
  (`FitViewport`, только портрет).

### 3.2. Пакеты (`internal/`)

| Пакет | Отвечает за |
|---|---|
| `Main.kt`, `screen/` | точка входа (`KtxGame`) и `GameScreen`, который связывает все системы и крутит кадр; фиксированный шаг логики (`FixedStepper`) |
| `model/` | неизменяемые данные: `Vec2`, `Entity` и виды, `Hitbox`, характеристики, снаряды, предметы, саммоны |
| `state/` | `GameState`: экран, мета-состояние, забег, реестр сущностей, инвентарь, слоты сохранений |
| `input/` | `InputSource` (`TouchInput`, `DesktopInput`), раскладка клавиш (`Control`, `KeyBindings`), расчёт целевой скорости корабля |
| `weapon/` | описания оружия (`Weapon`), режимы огня (`FireMode`, `Trigger`), расчёты по файлам + `ProjectileSystem` (полёт снарядов) |
| `logic/` | шаг игры `GameLogic`, спаун метеоритов, лут |
| `npc/` | поведение противников как данные (фазы, движение, атаки, переходы, окружение), движок ИИ, спаунер групп, саммоны + `NpcSystem` |
| `hazard/` | лучи и зоны: данные, доска опасностей, геометрия + `HazardSystem` |
| `physics/` | Box2D-мир, материалы, фильтр столкновений, сбор контактов, разбор ударов, урон |
| `content/` | виды противников, боссов, союзников; составы уровней; призывы игрока |
| `save/` | мета-состояние в Preferences, слоты, автосохранение |
| `ui/` | разметка кнопок экранов, действия, ввод интерфейса, слайдеры, бестиарий |
| `render/` | отрисовка поля, сущностей, лучей и зон, HUD и меню; шрифты |

Внутри пакета — несколько крупных файлов по смыслу (разделы отмечены `// --- … ---`), а не файл на класс:
например, все сущности — `model/Entities.kt`, движок ИИ — `npc/Ai.kt`, расчёты оружия — `weapon/Ballistics.kt`.
Подробное описание подсистем и файлов — в `docs/ARCHITECTURE.md`.

## 4. Как реализована логика

### 4.1. Кадр и фиксированный шаг

`GameScreen.render(delta)` каждый кадр:

1. `FixedStepper` переводит время кадра в целое число шагов по 1/60 с (кадр обрезается до 0.25 с, не больше 5 шагов —
   защита от «спирали смерти»), и столько раз вызывается `GameLogic.step(1/60)`.
2. `AutoSave.update()` пишет мета-состояние в выбранный слот, если оно изменилось и игра не в бою.
3. Отрисовка: поле → опасные зоны → сущности → лучи → интерфейс → FPS-оверлей.

Рендер идёт с частотой монитора (144+ FPS), логика и физика — всегда 60 Гц, поэтому поведение не зависит от FPS.

### 4.2. Шаг игры — `GameLogic.step(dt)`

Выполняется только на экране PLAYING, порядок важен:

| # | Что происходит | Где |
|---|---|---|
| 1 | время фазы, таймеры эффектов, перезарядка постоянных усилителей | `GameState.tick` |
| 2 | опрос ввода | `InputSource.poll()` → `ControlState` |
| 3 | эффекты на корабле: щит, ремонт | `applyEffects` |
| 4 | движение корабля к целевой скорости | `steer` |
| 5 | огонь: спуск → снаряды у дула или заявка на луч | `fire` |
| 6 | фаза: на уровне спаун метеоритов и групп противников, в бою — босс | `runLevel` / `runBossFight` |
| 7 | призывы игрока | `summonForPlayer` |
| 8 | ИИ противников и союзников: движение, выстрелы, призывы, лучи, зоны | `NpcSystem.step` |
| 9 | отметка встреченных видов для бестиария | `markSeen` |
| 10 | метеориты, влетевшие из-за края, снова держатся стенами | `letMeteorsIn` |
| 11 | снаряды в полёте: самонаведение, разрыв, сбивание встречных | `ProjectileSystem.step` |
| 12 | лучи и зоны: препятствие, урон, уничтоженные | `HazardSystem.step` |
| 13 | шаг Box2D, разбор ударов, удаление вылетевших | `PhysicsSystem.step` → `handle` |

Последствия (`handle`, `onDestroyed`): подбор усилителей, раскол метеорита и лут, деньги с противников,
награда и трофей с босса, game over.

### 4.3. Экраны и прогрессия — два конечных автомата

**Экраны** (`ScreenState` в `state/GameState.kt`):

```
MENU → SAVES → HANGAR ─┬─→ LOADOUT → PLAYING ⇄ PAUSE
                       ├─→ BESTIARY        │
                       └─→ META_SHOP       ├─→ SHOP (между уровнями) → PLAYING
                                           └─→ GAME_OVER / VICTORY → HANGAR

MENU, HANGAR, PAUSE ⇄ SETTINGS (кнопка-шестерёнка; возврат туда, откуда открыли)
```

**Фазы забега** (`Phase` в `state/GameState.kt`, переход — `GameState.advancePhase`):

```
Level(n) ──40 с──▶ BossFight(n) ──босс убит──▶ Shop(n) ──LEAVE──▶ Level(n+1)
                                   └─ после LAST_LEVEL (2) ──▶ VICTORY
```

`advancePhase` генерирует витрину магазина (3 случайных предложения из набора выпадающих предметов), открывает SHOP и
очищает поле перед новым уровнем. `bossDefeated` выдаёт деньги и трофей и решает: магазин или победа.

### 4.4. Физика и урон

- **Тела.** Игрок — dynamic; противник — dynamic (если «физичный») или kinematic; снаряды — bullet с непрерывной
  проверкой, пробивающие — сенсоры; усилители — кинематические сенсоры. Границы: стены, потолок (только для снарядов
  игрока), пол (только для корабля).
- **Фильтр столкновений** (`CollisionFilter`) — пары групп: PLAYER, METEOR, BOSS, ENEMY, ALLY, снаряды сторон,
  тяжёлые снаряды врагов, усилители, «влетающие из-за края».
- **Сбор и разбор ударов.** `ContactCollector` записывает удары до разрешения (скорости «до удара», точку контакта);
  `ImpactResolver` — чистый разбор: урон обоим, отскоки, пробитие, подбор, щит, секторы корпуса.
- **Формула урона** (`physics/Impacts.kt`):
  `урон = K × μ·|v_отн|²/2 × броня`, где `μ = m₁m₂/(m₁+m₂)` — кинетическая энергия в системе центра масс.
  Ниже порога 0.5 Дж урона нет. Броня — множитель входящего урона (корабли игрока ×4, под щитом 0).
  Секторы корпуса (`HitZone`) меняют урон по месту удара (например, нос Borer бьёт ×1.5, фронт держит ×0.5).

### 4.5. Управление кораблём

Ввод задаёт **целевую скорость**, а не позицию: импульс добирает её с ограниченным ускорением, поэтому толчки от
столкновений гаснут постепенно, а не стираются. Палец ведёт корабль к точке чуть выше себя; по Y подъём замедляется
к мягкому потолку на 2/3 поля, вниз — полная скорость. На desktop: мышь как палец и клавиатура по раскладке из настроек (по умолчанию стрелки — движение, S — огонь,
A/D/Z/X/C — слоты 1–5, P или Esc — пауза).

### 4.6. Оружие

- `Weapon` — sealed-иерархия `data object` с режимом огня и функцией `shots()`; виды: пулемёт, гатлинг, Гаусс, рикошет,
  ИК-ракеты, зенитка (Flak), лазер.
- Режимы огня (`FireMode`): Auto (зажатие), SemiAuto (нажатие), Charge (заряд, выстрел при отпускании), Beam (луч с нагревом);
  у любого режима может быть серия залпов. Состояние спуска — `Trigger` в `RunState`.
- Особая логика каждого оружия — чистые функции в своём файле `weapon/` (`Gauss`, `Ricochet`, `IrMissiles`, `Flak`, `Clash`).
- Снаряды (`ProjectileKind` + `ProjectileStats` в `Config.Projectile`): масса, отскоки, время жизни, пробитие, самонаведение,
  разрыв на осколки, сила сбивания (`breakPower`). Встречу двух снарядов считает сама игра, а не Box2D: Box2D не ловит
  столкновение «пуля–пуля» на высоких скоростях.

### 4.7. Противники и ИИ

- **Вид** — `NpcKind` в `content/`: тело (`NpcBody`), поведение, лут, роль (моб или босс), описание для бестиария.
  Сейчас: Gravel и Borer (мобы), Shard (босс), Drone (союзник).
- **Поведение — данные.** Сценарий из фаз; в фазе — движение (`Descend`, `Patrol`, `Stalk`, `Escort`), план атак
  (`Cycle` из шагов `Burst`, `Summon`, `Laser`, `Hazard`), условие перехода (`HealthBelow`, `After`, `Kills`, `AnyOf`) и окружение
  (метеориты из-за краёв). Особое поведение — `Custom` со своим кодом в файле вида и состоянием в `Memory`.
- **`think`** — чистая функция шага ИИ, возвращает приказы (`Orders`); `NpcSystem` применяет их: физичное тело ведёт
  импульсами, нефизичное — скоростью, поворачивает корпус, создаёт снаряды, призывы, лучи и зоны.
- **Появление** — `NpcSpawner`: группа выбирается по весам записей уровня (`content/Levels.kt`), паттерн — строй
  (ряд, клин, колонна), волна или засада из-за бокового края. Пока жив босс, обычный спаун молчит.
- **Саммоны** — призванные противники и союзники с лимитами (`SummonSpec`): сколько за раз, сколько живых, время жизни,
  исчезновение с призывателем, переход между уровнями.

### 4.8. Лучи и опасные зоны

Не тела Box2D, а данные на доске опасностей (`HazardBoard`). Луч заявляется каждый шаг; `HazardSystem` находит первое
препятствие и наносит урон как энергию «мощность × dt» по той же формуле (без порога). Зоны — круги со сроком жизни,
ранят выбранные стороны. У лучей и зон врагов есть предупреждение без урона.

### 4.9. Инвентарь, деньги, магазины

- 5 слотов: 1 — оружие корабля, 2 — подвес, выбранный в LOADOUT, 3–5 — подобранное. Типы слотов: оружие (сделать текущим),
  постоянный усилитель (эффект или призыв + перезарядка), расходник, заглушка.
- Временные эффекты: щит, ремонт, тяжёлые снаряды; повторная активация продлевает.
- Хранилище постоянных предметов — бесконечное (трофеи с боссов, товары магазина меню).
- Деньги (`Wallet`) — за метеориты с шансом, за противников и боссов. Тратятся в магазине между уровнями,
  в магазине меню, в ангаре (корабли Rebel, Glory, Greedy) и в снаряжении (подвесы).
- Случайность (спаун, лут, витрина) — через внедрённый `Random`, поэтому всё воспроизводимо в тестах.

### 4.10. Сохранения

- Сохраняется только мета-состояние: деньги, корабли, подвесы, выбор, товары, встреченные виды (формат v3, ключи в `Config.Save`).
- Несколько слотов: слот N — LibGDX Preferences `spaceace-save-N`, индекс занятых — `spaceace-saves`.
- Настройки (раскладка клавиш) — отдельный файл `spaceace-settings`, общий для всех слотов; пишется сразу при изменении.
  Desktop — `%USERPROFILE%\.prefs\`, Android — SharedPreferences.
- Запись — при изменении вне боя, а также принудительно при сворачивании и закрытии. Повреждённые и неизвестные
  значения при загрузке не роняют игру.

### 4.11. Интерфейс и рендер

- Свой лёгкий UI без Scene2D: одна функция разметки (`layout`) возвращает кнопки экрана в виртуальных пикселях;
  по ней и рисует `UiRenderer`, и ищет нажатие `UiController`. Действия (`UiAction`) применяются к `GameState`.
- Слайдеры (`Carousel`) — ангар, подвесы, слоты сохранений, бестиарий: стрелки, свайп, клавиши.
- Рендер — `ShapeRenderer` по хитбоксам с поворотом корпуса, кольцо щита, лучи и зоны, HUD (HP, деньги, фаза, слоты,
  полоса HP босса, заряд и нагрев оружия). Цвета — `Config.Render`.

## 5. Сборка и запуск

Нужен **JDK 21**: путь к нему одной строкой в `jdk-path.txt` (файл в `.gitignore`). Системный JDK 25 с этой версией
Gradle/Kotlin не работает.

| Задача | Как |
|---|---|
| Играть | `run.bat` |
| Играть с логом | `run-debug.bat` → `logs\run-<дата-время>.log` (UTF-8, окно не закрывается после выхода) |
| Играть, не трогая тесты | `run_wout_tests.bat` (то же с логом, Gradle с `-x test`) |
| Тесты | `$env:JAVA_HOME = "C:\#MyData\jdk-21.0.12.1"; .\gradlew.bat core:test` |
| Один тест | `.\gradlew.bat core:test --tests "com.spaceace.game.ui.BestiaryTest"` |
| Сборка всего | `build.bat` (тесты, desktop, android) → `build-log.txt` |

При вылете стек ошибки — в свежем логе `run-debug.bat` между `> Task :desktop:run` и `BUILD`.

## 6. Тесты

JUnit 5 + kotlin.test, пакеты повторяют `main`:

- **чистые правила** — урон, оружие, ИИ и контент, спаун, саммоны, лучи и зоны, инвентарь и магазины, сохранения, фиксированный шаг;
- **интерфейс без окна** — разметка экранов, переходы, слайдеры, перенос текста, размеры шрифта, цвета;
- **настоящий Box2D без окна** — отскоки, толчки, засада, вращение, пробитие, движение корабля, полёт снарядов, саммоны;
- **полный забег** (`GameLoopTest`) — бот играет на настоящем Box2D: бессмертный бот доходит до VICTORY.

Окно и OpenGL тестам не нужны: логика от рендера не зависит.

## 7. Состояние проекта

- Играбельно на desktop: меню, слоты сохранений, ангар, снаряжение, бестиарий, два уровня с боссом, магазины.
- Графика: спрайты кораблей, противников, босса и метеоритов; звёздный фон с параллаксом. Запуск на Windows и Linux
